# ScholarFlow · AI 论文共读与脉络梳理平台

> 把「每周几十篇 PDF 读不完」拆成一条可控的流水线：**导入 → 三层摘要 → 四栏沉淀卡 → 脉络图 → 共读小组 → 个人知识库 → 订阅分层**。

## 1. 这是什么

一个面向研究生与课题组的**论文共读工作台**原型。它解决的不是「怎么下载论文」，而是后面三件事：

1. **读完就忘** —— 摘要写得像宣传稿，两周后只剩模糊印象；
2. **笔记散落** —— 批注在 PDF 里、想法在聊天记录里、结论在脑子里，写综述时临时翻找；
3. **脉络断链** —— 自动生成的引用图布局混乱，方法相近的论文未必互引，看不出演进关系。

ScholarFlow 用七个一级模块把这三件事收敛到同一条流水线上，并对每个模块都写了可量化的验收口径（见 `docs/ScholarFlow_产品方案清单.md`）。

### 当前版本的性质

本仓库是一个**单文件可交互原型**，内部使用内置演示文献数据：

- 纯前端，`index.html` 双击即可运行，**不发任何外部网络请求**；
- 页面中的文献、摘要、批注均为**演示数据**，用于呈现流程与交互逻辑；
- 设计清单中标注的 pdf.js / GROBID / OCR / Yjs 协同等能力，属于**方案设计目标**，当前原型未接入后端与模型服务；
- 当前版本**不使用 localStorage**，刷新页面即回到初始演示状态。

### 方式一：在线打开（最省事）

直接访问 Pages 地址：https://px-pangu.github.io/scholarflow/

```bash

cd scholarflow
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

## 4. 功能模块详解

### 01 文献导入

- **痛点**：PDF 散落在邮箱、课题组群与硬盘，没有统一元数据，检索靠猜文件名。
- **功能**：批量上传 PDF / DOI / arXiv；自动抽取标题、作者、年份、期刊与参考文献；同 DOI 去重与版本合并提示；解析队列显示进度与失败原因。
- **交互**：拖入文件 → 进入解析队列 → 元数据校对弹窗（可人工修正）→ 打标签归入课题 → 进摘要队列。
- **验收口径**：20 页 PDF 上传 + 解析 P95 ≤ 60s；元数据准确率 ≥ 95%（抽样 100 篇）；单批上限 50 份。

### 02 AI 三层摘要

- **痛点**：摘要读完抓不住结论，事后重读成本极高。
- **功能**：一句话结论 / 300 字要点 / 结构化拆解三层摘要；每条结论可跳转原文页码并高亮；摘要可编辑并保留历史版本，可回滚。
- **技术实现要点**：按章节分段摘要再汇总；**每条结论绑定 `(page, bbox)` 锚点**；输出走 JSON Schema 强校验，缺页码即触发重生成。
- **验收口径**：三层摘要 P95 ≤ 60s（20 页）；**可溯源率 100%**，页码准确率 ≥ 98%；保留版本 ≥ 10 个。

### 03 四栏沉淀卡

- **痛点**：笔记无法横向对比同类研究。
- **功能**：每篇一张「问题 — 方法 — 结论 — 局限」四栏卡，AI 预填草稿且可编辑；局限栏可关联后续论文的改进点；批量导出 BibTeX / Markdown / 表格。
- **技术实现要点**：卡片 schema 固定四字段 + 自定义字段；格内引用存 `(page, span)` 锚点，原文变更时标记失效；导出走服务端渲染。
- **验收口径**：AI 预填覆盖率 ≥ 90%；100 张卡导出 ≤ 5s；编辑本地自动保存，断网不丢失。

### 04 脉络图

- **痛点**：自动引用图布局杂乱不可控，同类方法互不引用导致脉络断链。
- **功能**：基于参考文献自动生成有向引用图；节点可拖拽并锁定；方法相近的论文可**强制连线**并标注「疑似方法相似」。
- **交互**：展开脉络 → 拖拽节点锁定 → 框选两篇强制连线 → 填写相似理由 → 生成带标签的虚线边 → 存为个人 / 小组视图。
- **验收口径**：100 节点图首屏 ≤ 1.5s；拖拽 ≥ 50fps；强制连线 100% 可撤销；删除论文时关联边显式提示。

### 05 共读小组

- **痛点**：组会讨论停在口头，段落级意见散在群里，缺席者无法还原上下文。
- **功能**：建组并指派精读篇目与截止时间；段落级批注与串式讨论，批注锚定到句子；实时在线状态与光标，支持 50 人同篇在线；讨论可收敛为「待决议」并导出组会纪要。
- **技术实现要点**：CRDT（Yjs）+ WebSocket 保证并发一致；锚点失效降级为提示而非静默丢失；权限分读写 / 只读两级。
- **验收口径**：50 人在线时批注同步 ≤ 300ms；冲突合并零丢失。

### 06 个人知识库

- **痛点**：读过的东西检索不到，也不清楚自己的阅读积压有多少。
- **功能**：全文 + 批注 + 卡片统一检索，按标签 / 年份 / 方法 / 局限筛选；按课题聚合卡片生成综述大纲；阅读统计（篇数、页数、积压）。
- **技术实现要点**：中文分词与向量检索混合召回；引注 `(作者, 年份, p.x)` 自动生成；草稿模板可配置。
- **验收口径**：10 万条记录检索 P95 ≤ 500ms；Top10 命中率 ≥ 85%；**引注页码正确率 100%**。

### 07 订阅与定价

- **痛点**：课题组有共同预算但个人付费意愿低，免费版限制不明，试用即流失。
- **功能**：免费版 / 实验室版分层，差异在篇数、协作人数、脉络节点数；实验室版按席位订阅，含成员管理与用量看板；临近上限提前提示，不静默中断。
- **验收口径**：配额判定 ≤ 1s；到期后数据可导出率 100%；全量导出包 ≤ 30 分钟生成。

## 6. 硬约束（产品的红线）

这些约束写在设计清单里，是本项目的**产品伦理边界**，不是可选项：

1. **不做通用网盘，不做聊天机器人** —— 只做论文共读这一件事；
2. 一级模块锁定为 **7 个**，不无限扩张；
3. **所有 AI 结论必须带原文页码定位**，无出处不生成 —— 宁可不出结论，也不出无法溯源的结论；
4. **用户批注只可归档，永不自动删除** —— 删除论文时也要显式提示关联边。

## 7. 关键数据结构（方案层）

| 对象 | 主要字段 |
|---|---|
| 文献 | `doc_id`, `title`, `authors[]`, `year`, `venue`, `doi`, `refs[]`, `tags[]` |
| 摘要层 | `level(1/2/3)`, `text`, `anchors[(page, bbox)]`, `version` |
| 沉淀卡 | `problem`, `method`, `conclusion`, `limitation`, `custom{}`, `cite_anchors[]` |
| 脉络边 | `from`, `to`, `type(ref/user)`, `label`, `locked`, `sim_reason` |
| 批注 | `span`, `thread[]`, `author_role`, `status(active/archived)` |

---

## 8. 隐私与数据

- 当前原型**纯本地运行，不上传任何数据，不含统计与追踪脚本**；
- 设计目标中，用户文献与批注归属用户本人，欠费只停 AI 能力，不动数据；
- 导出包采用开放格式（BibTeX / Markdown / CSV），保证随时可迁移。

---

## 9. 已知限制

- 原型不含后端：文件解析、AI 摘要、实时协同均为**流程与界面演示**；
- 未接入真实 PDF 解析与 OCR，导入的是演示文献；
- 无持久化：刷新页面即重置；
- 未做移动端适配优化，建议桌面浏览器使用。
